
# Runbook — Агент-диспетчер по возвратам

## 1. Назначение

Инструкция по запуску и использованию учебного приложения
«Агент-диспетчер по возвратам» компании «Клевер Маркет».

Приложение анализирует обращения клиентов, предлагает
маршруты обработки и передаёт окончательное решение менеджеру.

## 2. Запуск приложения

Открыть папку `return-dispatcher-starter` в VS Code.

Активировать виртуальное окружение:

    source .venv/bin/activate

Запустить Flask:

    python -c "from app import app; app.run(port=5001, debug=True)"

Открыть в браузере:

http://127.0.0.1:5001/

Для остановки сервера нажать Ctrl + C.

## 3. Работа с обращениями

1. Выбрать обращение RC-6001–RC-6016 в левой колонке.
2. Проверить письмо клиента и данные заказа.
3. Изучить историю предыдущих обращений.
4. Просмотреть сохранённый маршрут ИИ.
5. Проверить обоснование и применимые правила.
6. Прочитать черновик клиенту и комментарий менеджеру.

Сохранённая карточка загружается из SQLite без повторного вызова модели.

## 4. Обработка обращения через ИИ

Если сохранённого анализа ещё нет:

1. Нажать «Анализировать с ИИ».
2. Ввести ключ менеджера.
3. Получить рекомендацию от внешней модели.
4. Проверить результат.

Допустимые маршруты:

- RECOMMEND_APPROVE
- RECOMMEND_DENY
- NEED_MORE_INFORMATION
- MANUAL_REVIEW
- DUPLICATE_OR_PROCESSED

ИИ не принимает окончательного решения.

## 5. Подтверждение менеджером

Менеджер проверяет рекомендацию и выбирает
итоговое решение.

Если решение отличается от рекомендации ИИ,
необходимо указать причину изменения.

Для подтверждения требуется MANAGER_API_KEY.

Окончательное решение сохраняется в SQLite.
Повторное подтверждение одного дела запрещено.

Если сведений недостаточно или требуется ручная проверка,
дело можно оставить без окончательного решения.

## 6. Учебное разрешение на возврат

Учебное разрешение создаётся только при условиях:

- рекомендация ИИ — RECOMMEND_APPROVE;
- решение менеджера — APPROVED;
- решение подтверждено менеджером.

Пример: TRAIN-RC-6016.

Для других маршрутов автоматическая выдача
учебного разрешения запрещена.

Реальных финансовых операций приложение не выполняет.

## 7. Обработка очереди из 16 обращений

В терминале выполнить:

    python test_ai.py

Скрипт обрабатывает обращения, для которых
ещё нет сохранённого анализа.

Результаты сохраняются в SQLite.

Для экспорта полной таблицы выполнить:

    python export_results.py

Итоговый файл:

    case-results.md

## 8. Ошибки и восстановление

Если сайт не открывается:
- проверить, запущен ли Flask;
- проверить адрес http://127.0.0.1:5001/;
- посмотреть сообщения в терминале сервера.

Если модель возвращает некорректный JSON:
- результат не должен приниматься как корректная рекомендация;
- проверить тип ошибки;
- повторить обработку неуспешного обращения.

Если OpenRouter недоступен:
- проверить подключение к интернету;
- проверить настройки API;
- учесть ограничения бесплатных моделей.

Если менеджер получает ошибку доступа:
- проверить наличие MANAGER_API_KEY в файле .env;
- убедиться, что используется ключ менеджера,
  а не ключ OpenRouter.

## 9. История и безопасность

SQLite хранит анализы, рекомендации, решения менеджера
и учебные разрешения на возврат.

Исходные файлы data/ и policy/ не изменяются агентом.

Файл .env содержит секретные ключи и не должен
попадать в GitHub.

Приложение не выполняет:
- банковские операции;
- изменение внешних заказов;
- автоматическую отправку писем;
- реальные возвраты денежных средств.

Все клиентские сообщения остаются черновиками.

- README.md
- spec.md
- AGENTS.md
- agent-spec.md
- agent-decision-card.md
- case-card.md
- runbook.md

Подготовить пять скриншотов:
- два скриншота интерфейса приложения;
- три скриншота обращений RC-6014, RC-6015, RC-6016
  с результатами и решениями по ним.

Проверить, что секретные ключи не включены
в материалы для сдачи.
