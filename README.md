# Кто выгуливает Бориса

Учебный Node.js micro-MVP для вымышленной компании «Догяндекс». Общая страница помогает сотрудникам записываться на прогулку с Борисом и отмечать последнее кормление.

## Реализовано

- Показываются текущая дата и пять слотов прогулок: 09:00, 11:00, 13:00, 15:00 и 17:00.
- Свободные и занятые слоты различаются; у занятого отображается ФИО.
- Свободный слот бронируется через сервер и атомарный conditional `UPDATE` в SQLite. Повторный запрос получает конфликт, исходное ФИО сохраняется.
- ФИО очищается от лишних пробелов; пустое значение отклоняется сервером.
- Если заняты все пять слотов, форма записи скрыта и показывается popup «Борис гуляет весь день. Возможность записи откроется завтра».
- Карточка показывает ФИО и время последнего кормления. Каждая отметка хранится в SQLite; пустое ФИО отклоняется.
- Подтверждения открываются в модальном окне. Отправка booking/feeding-форм обновляет соответствующую часть страницы без полной навигации и сохраняет положение прокрутки.
- Интерфейс адаптируется к широкому и узкому экрану; локальные ресурсы — `styles.css`, `app.js`, оригинальная `boris.svg` с хвостом-вопросительным знаком.

## Главный сценарий

Сотрудник открывает страницу, выбирает свободное время на сегодня, вводит синтетическое ФИО, например «Анна Тестова», и подтверждает запись. Слот становится занятым. Повторная попытка не меняет первоначальную запись. Состояние хранится в SQLite и доступно после обновления или из второго браузера/контролируемого запуска.

Дополнительно страница показывает время и ФИО сотрудника, который последним отметил кормление, и позволяет отметить новое кормление.

## Технические границы

- Минимальный Node.js-проект с локальным запуском через npm.
- Настоящий SQLite-файл `boris.sqlite` в папке проекта; таблицы `walk_slots` и `feedings` созданы по схеме из [spec.md](spec.md). Сервер валидирует ФИО, атомарно записывает только свободный слот и сохраняет кормления в `feedings`.
- Визуальные ресурсы локальные: `styles.css`, `app.js` и оригинальная `boris.svg`; внешние UI-фреймворки и изображения не подключаются.
- Для текущей даты создаются ровно пять фиксированных слотов. ФИО для прогулки и кормления очищается от лишних пробелов и не может быть пустым.
- Сервер отвечает за проверку и защиту от повторного бронирования; состояние не подменяется `localStorage`, памятью процесса, моками или статичной разметкой.
- Интерфейс должен оставаться читаемым и пригодным для сценария на широком и узком экране.
- Используются только синтетические ФИО и значения.
- Вне проекта: авторизация, роли, корпоративные данные, администрирование, отмена записи, календарь на неделю, уведомления, история действий, интеграции, внешние сервисы, обязательный деплой и production-grade эксплуатация.

## Локальный запуск

Из корня проекта выполните:

```powershell
npm.cmd start
```

Затем откройте в браузере http://127.0.0.1:3000/. В текущей PowerShell-среде используйте `npm.cmd start`: вызов `npm` блокируется политикой для `npm.ps1`. В оболочке, где npm запускается штатно, используйте `npm start`. Запуск проверен на Node.js v26.13.0 и npm 11.20.0; используется встроенный `node:sqlite`, внешние зависимости не нужны.

## Проверки и ограничения

Финальная техническая проверка от 2026-11-02: `GET /` возвращает HTTP 200; отображаются дата и пять времён; при занятой сетке форма скрыта и показывается full-day popup; stale booking получает `409`; пустые ФИО отклоняются с `400`; локальные CSS/JS/SVG возвращают `200`. Ранее успешная запись, атомарный конкурентный конфликт, сохранение после повторного GET/второго клиента и два кормления проверялись в изолированных тестах. Viewport 1440 и 390 px не показали горизонтального переполнения. Подробный статус каждого DoD находится в [PLAN.md](PLAN.md).

Границы MVP: нет авторизации, ролей, отмены записи, дополнительных дат, расписания/истории кормлений, уведомлений, интеграций, внешних сервисов и обязательного деплоя. Для демонстрации используйте только синтетические ФИО. Текущую рабочую БД нельзя автоматически считать синтетической: для скриншотов создайте изолированную копию с тестовыми данными. См. [SUBMISSION.md](SUBMISSION.md).
