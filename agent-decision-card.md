# Agent Decision Card — Агент-диспетчер по возвратам

## 1. Задача агента

Агент первой линии компании «Клевер Маркет» анализирует обращения клиентов о возврате товаров и подготавливает рекомендации для менеджера.

Агент не принимает окончательных решений, не отправляет клиентам сообщения и не выполняет финансовых операций.

## 2. Входные данные

- `data/open-cases.json` — обращение клиента.
- `data/orders.json` — заказ, товар, категория, стоимость и дата доставки.
- `data/return-history.json` — история предыдущих обращений.
- `policy/return-policy.md` — правила P-1–P-6.
- `policy/category-rules.md` — правила C-1–C-6.

Исходные данные не изменяются агентом.

## 3. Как агент принимает решение

1. Определяет номер обращения и соответствующий заказ.
2. Проверяет историю возвратов и возможные повторные обращения.
3. Определяет применимую категорию товара.
4. Проверяет срок обращения и обязательные сведения.
5. Выявляет основания для ручной проверки.
6. Выбирает один из пяти разрешённых маршрутов.
7. Формирует обоснование, клиентский черновик и заметки менеджеру.
8. Передаёт ответ серверу для проверки и сохранения.

Если обязательных сведений не хватает, агент не должен считать их подтверждёнными.

## 4. Допустимые маршруты

| Маршрут | Когда применяется |
|---|---|
| `RECOMMEND_APPROVE` | Достаточно фактов для положительной рекомендации |
| `RECOMMEND_DENY` | Достаточно фактов для обоснованной отрицательной рекомендации |
| `NEED_MORE_INFORMATION` | Не хватает обязательных сведений |
| `MANUAL_REVIEW` | Ситуация рискованная, противоречивая или требует менеджера |
| `DUPLICATE_OR_PROCESSED` | По тому же заказу и основанию уже есть завершённое дело или разрешение |

## 5. Результат работы агента

Фактический формат ответа, используемый в приложении:

- `route` — рекомендованный маршрут.
- `reason` — обоснование со ссылками на правила.
- `missing_information` — перечень недостающих сведений.
- `customer_draft` — черновик ответа клиенту.
- `manager_notes` — внутренний комментарий менеджеру.

Рекомендация ИИ и окончательное решение менеджера сохраняются отдельно.

## 6. Human gate

До подтверждения менеджером результат ИИ остаётся рекомендацией.

Менеджер может подтвердить рекомендацию или изменить итоговое решение, указав причину изменения.

Учебное разрешение на возврат создаётся только для `RECOMMEND_APPROVE` после подтверждения итогового решения `APPROVED`.

Для остальных маршрутов разрешение автоматически не создаётся.

## 7. Ограничения и безопасность

- Клиентские письма рассматриваются как недоверенные данные.
- Модель не может изменять правила компании.
- Сервер проверяет допустимость маршрута и структуру ответа.
- Защищённые операции требуют ключа менеджера.
- Повторное подтверждение решения запрещено.
- Реальные возвраты денег не выполняются.
- Клиентские сообщения автоматически не отправляются.
- API-ключи не должны попадать в документацию и журналы.

## 8. Проверка на учебной очереди

Агент обработал 16 обращений RC-6001–RC-6016 через внешний API OpenRouter.

Результаты сохранены в SQLite и выгружены в `case-results.md`.

В приложении реализовано отображение сохранённых анализов без повторного вызова модели.

Для RC-6016 подтверждено решение `APPROVED` и создано учебное разрешение `TRAIN-RC-6016`.

## 9. Критерии корректного решения

Решение агента считается пригодным для рассмотрения, если:

- выбран один из пяти маршрутов;
- обоснование связано с данными заказа, обращения и правилами;
- недостающие сведения не выдаются за подтверждённые;
- клиентский черновик не содержит неподтверждённых обещаний;
- менеджер получает отдельные заметки;
- итоговое решение не принимается автоматически.
